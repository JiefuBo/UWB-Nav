# UWBNav Wi-Fi 回传与定位上位机

## 交付内容

- `firmware/UWB_C3_WiFi/UWB_C3_WiFi.ino`：ESP32-C3 Arduino 程序，中文注释。
- `host/server.py`：Python 后端，使用标准库，无需 pip 安装包。建议 Python 3.9 或更新版本。
- `host/static/`：HTML/CSS/JavaScript 地图界面，直接由后端提供。
- `host/simulate.py`：明确标注“模拟数据”的两标签演示输入，不能当作实测结果。
- `host/tests/test_backend.py`：解析、布局和定位测试。
- `界面预览_模拟数据.png`：模拟输入的界面预览。

本版本审阅并沿用了此前 TR3.9-GC-ZC V1.2 手册的二进制上报格式。
实际收到的 `45 91 01 00 01 00 00 00 03 00 C5 36 AF` 表示：对端基站 ID 3，距离 197 cm。
固件版本字段两字节保留，未猜测其版本号编码。
CRC 使用反射多项式 0x8408、初值0、最终异或0，覆盖含帧头的前部字节，帧内 CRC 高字节在前。
这些参数与手册两例和用户三组实测样本一致。

## 1. 先启动电脑上位机

电脑和 ESP32 接入可相互通信的同一局域网。C3 使用 2.4 GHz Wi-Fi；电脑可以在同一双频路由器的另一频段。
**相同 SSID 并不保证通信：访客网络、校园客户端隔离、VPN和防火墙可能阻止设备互通。**
程序适合普通密码 Wi-Fi；未实现校园 WPA2-Enterprise 的账号认证流程。测试时建议使用普通路由器或手机 2.4 GHz 热点。

进入解压文件夹的 `host`，运行：

```sh
python3 server.py
```

Windows 可以使用：

```bat
py server.py
```

或使用 host 内的启动脚本。Mac 双击脚本前，如无执行权限，可在终端用 `bash start_mac.command` 启动。
程序显示电脑候选局域网 IPv4。请在系统网络设置中确认实际连接同一 Wi-Fi 的网卡 IP，避免误填 VPN 地址。
浏览器打开 `http://127.0.0.1:8000`。不要直接双击 HTML 文件。
后端 HTTP 端口为 TCP 8000，ESP32 回传端口为 UDP 7788。系统提示网络权限时允许 Python 在该局域网接收连接。
关闭所有程序后端窗口会停止数据接收。Ctrl+C 可停止后端。

## 2. 修改 C3 必填参数并上传

Arduino IDE 打开 `firmware/UWB_C3_WiFi/UWB_C3_WiFi.ino`，保留同目录的 `RangeFrameParser.h`，修改顶部：

```cpp
const char *WIFI_SSID = "你的Wi-Fi名称";       // 必填
const char *WIFI_PASSWORD = "你的Wi-Fi密码";   // 必填
const char *PC_IP = "192.168.1.100";          // 改成电脑Wi-Fi网卡IPv4
const char *LOCAL_ROLE = "tag";              // 移动标签端
const char *LOCAL_ID_HEX = "10";             // 本机UWB实际ID，十六进制
constexpr uint8_t RECORDS_PER_FRAME = 1;      // 当前13字节帧为1
```

例如两个移动标签实际 ID 为十六进制 `10`、`11`，对应两台 C3 分别填写 `10`、`11`。
此身份参数只用于标识回传数据，**不会修改 UWB 模块自身的 ID 或工作角色**；请先通过配置软件/AT将两者设为一致。
每台 C3 都需要上传自身参数。同角色不同 UWB 设备不得使用重复 ID。
本机身份必填，因为距离帧中只含对端 ID，无法仅从原始帧推断发送标签是谁。

IDE 选择 `ESP32C3 Dev Module` 或对应板型。原生 USB 接口启用 `USB CDC On Boot = Enabled`。
上传后串口监视器选择 115200。UWB UART 固定为 921600、8N1。

## 3. 接线与状态灯

| 接口 | 接线 |
|---|---|
| UWB TX | C3 GPIO1，接收 |
| UWB RX | C3 GPIO0，发送 |
| UWB GND | C3 GND，共地 |
| 红色 LED | C3 GPIO2 |
| 黄色 LED | C3 GPIO3 |
| 绿色 LED | C3 GPIO4 |

默认 LED 接法：GPIO → 适当限流电阻（例如330Ω）→ LED正极；LED负极 → GND。
若你的电路低电平点亮，将 `LED_ACTIVE_HIGH` 改为 `false`。
GPIO2 是 ESP32-C3 启动绑带引脚。LED电路不能强制改变复位时所需电平；如接灯后启动异常，先断开红灯电路确认并调整其接法。
UWB供电按实际板卡手册连接，UART需兼容3.3V逻辑。

- 黄色：正在连接 Wi-Fi。
- 绿色：Wi-Fi 已连接，**不代表电脑已成功收到 UDP**；请同时查看网页设备状态。
- 红色：一次连接超过15秒；等待5秒后自动重试，重试时转黄色。
- 已联网后掉线：转入重新连接过程。

程序连接 Wi-Fi 时不阻塞串口读取。未联网的串口数据被丢弃并计数，不会恢复网络后回放旧测距。
AT指令仍可以通过电脑串口监视器发送，行结束选“换行”或“回车和换行”。
AT配置前需要按手册将 **UWB自己的GPIO17** 拉低；正常测距时恢复高电平/悬空。

## 4. 四基站布局与定位

网页右侧填入基站 A/B/C/D 的真实模块 ID，**使用十六进制**，例如 `1`、`2`、`3`、`4`。
字母 A/B/C/D 是显示名称，不是模块 ID。

有三种布局方式：

1. **矩形快速布局**：例如 AB=10m、BC=20m，选择矩形假设，填入 A左上、B右上、C右下、D左下。
   坐标为 A(0,20)、B(10,20)、C(10,0)、D(0,0)。四个点也可单独选择展示位置。
2. **六组距离重建**：输入 AB、BC、CD、DA、AC、BD，选择 C/D 在 AB上方或下方。
   以 A为原点、AB为正X轴；输出坐标建议，检查一致性提示后再保存。
   此功能假设水平平面距离；不同高度测得的斜距需先换算成水平距离。
   CD用于检查重建结果一致性；不一致时会警告，不能把警告坐标视作已经标定成功。
3. **直接坐标编辑**：填写已测绘的 X、Y、Z，点击“保存布局与设置”。

仅“AB=10、BC=20”不能唯一确定任意四边形，所以快速方式显式采用矩形假设。
点位近似共线会被拒绝。坐标原点和朝向是地图约定，不改变 UWB 工作方式。
四基站标签应按外围顺序排列，便于图中的边界连线；计算使用各自真实坐标。

上位机以四距离做二维非线性最小二乘，输出标签 X/Y；标签 Z固定在右侧指定的高度。
输入为 UWB 的实际距离，内部单位米。锚点 Z和标签 Z需采用同一高度参考。
四个基站距离必须都收到、在过期窗口内且时间跨度不超过默认2.5秒。
缺少距离、过期或跨度过大时不显示新的位置。默认过期4秒，可在界面修改。
`config.json` 中可调整 `max_span_seconds`（应根据硬件更新率与用户运动速度谨慎设置）。
屏幕 RMS 是距离拟合残差，**不是实测位置误差**；大残差会提示位置可信度较低。
算法不会强行把估计点夹在矩形内，以免掩盖测距误差或实际越界。

标签可以点击“命名”改成“标签A”“标签B”。侧栏展示每个标签对应四基站的距离及数据年龄。
地图支持滚轮缩放、拖动平移和“适应地图”。

## 5. 固定物体

在右侧输入名称、类型、X/Y即可添加厕所、登机口或导航终点。目标点会显示在地图上，可以删除。
保存的布局、目标点和标签名称保存在 `host/config.json`，重启仍保留。
此版本实现目标点展示，尚未实现通行区域、墙体或避障路径规划。

## 6. 原始字节传输与数据可靠性

C3 每次收集最多128个 UART 原始字节，或在3ms串口空闲时发送一个 UDP JSON 包。
包中的 `hex` 是原始字节的无损十六进制表示，不是打印文本。Python恢复字节后按帧头/长度/CRC解析。
包还包含 MAC设备标识、启动会话、递增序号、本机角色、本机ID及每帧记录数。
串口拆包/连续帧都由后端流式解析处理。缺包时清除不完整帧；重复/乱序包不会覆盖新距离。
UDP没有交付确认，可能丢包。缺包数和CRC失败数可在网页“设备与原始串口数据”查看。
每秒发送空字节心跳，方便区分“设备在线”和“已收到有效测距帧”。
原始数据仅在内存保留最近80条，不自动长期保存位置轨迹。C3本地串口仍打印可读距离；需要原始HEX调试时将 `PRINT_RAW_HEX` 改为true。

手册多标签帧不含记录数量字段：`RECORDS_PER_FRAME` 必须与实际帧格式一致。
`AT+OTOTAL` 是基站一次输出的标签记录数，不是“基站总数量”；标签看到四基站不等于需填4。
当前实测每帧13字节应保持1。若固件输出格式不同，应提供实际抓包再修改解析。
软件不会让 UWB 自动获得四个基站距离；仍需要硬件固件和测距调度支持。

## 7. 无硬件演示和排查

先启动后端，再另开终端在 `host` 运行：

```sh
python3 simulate.py
```

网页会显示两个模拟标签 A1/A2，并在顶部标为“模拟数据”。不要在实测记录时同时运行模拟器。
停止模拟器后约4秒，模拟标签的位置会消失并提示过期。

排查顺序：

1. C3黄色/红色：检查SSID、密码、2.4GHz网络。
2. C3绿色但网页无设备：核对电脑IP、UDP7788、防火墙、访客/客户端隔离。
3. 网页设备在线但有效帧为0：检查UWB供电、共地、921600波特率、GPIO17是否退出配置状态、实际帧格式。
4. 有距离但没有位置：检查四基站ID映射，是否全部有新鲜距离，设备能否测到四基站。
5. 位置明显错误：重新测绘布局、检查米/厘米和高度，排查遮挡、多径、距离校准及四距离时间跨度。
